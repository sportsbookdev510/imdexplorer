    I found no defects in the Conditionals (COND) token's economics. .imd-findings.json has an empty findings list and six coverage rows, all holds.

    What the code is: src/Conditionals.sol is an OpenZeppelin v5.1 ERC20 with nothing added. Its constructor mints 1_000_000_000 * 10 ** 18 once to msg.sender (the factory). The vendored OpenZeppelin ERC20.sol matches the standard v5.1 code for transfer, approve, transferFrom, _approve, _spendAllowance and _update.

    The three guides:

    • Economic Security: there are no fees, burns, taxes, hooks or price-dependent logic. That means no value can be pulled out, and nothing a privileged account could abuse.
    • Invariant: total supply stays at exactly 10²⁷. The only mint is in the constructor, and no public function can mint or burn. The token uses the default 18 decimals. Each transfer subtracts from one balance and adds the same amount to another, and a failed transfer changes nothing.
    • Flow Gap: because no transfer charges a fee, every launch flow moves exactly the amount requested. That covers the factory sending the swarm share to the distributor, seeding the pool through the PoolManager, swaps in both directions, and distributor claims. There's no owner, pause, blacklist, freeze, burnFrom, delegatecall or selfdestruct.

    The three entry points:

    • approve sets the allowance to the exact value and rejects a zero owner or spender. The known ERC20 race when an existing allowance is overwritten applies to every ERC20, not to this code, so I didn't report it.
    • transfer moves exactly the amount and reverts cleanly on an insufficient balance.
    • transferFrom reduces a finite allowance by exactly the amount and leaves an unlimited (max) allowance unchanged.

    Static analysis: the one aderyn lead, a large number at line 10, is just the supply constant, which is correct.

    Checks run: the existing forge test suite passed (31 of 31). I didn't run the protected launch tests, because they import v4-core and src/LaunchLiquidity.sol, which aren't in this tree. I modified no project files.
