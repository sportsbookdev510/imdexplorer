Build "SqueekVision" — a real-time SqueekChain network dashboard as a single-page web app.

Must include:

  1. Live Squeektoshi wheel status (running/idle, RPM, speed, distance) from GET https://api.squeekchain.com/v1/status
  2. Animated block progress bar showing next block completion percentage
  3. $SQK token economics (minted, circulating, max cap) from GET https://api.squeekchain.com/v1/economy/state
  4. Settlement history table with time-range tabs (now/24h/7d) from GET https://api.squeekchain.com/v1/settlements
  5. Hourly activity bar chart from settlement buckets
  6. Contract addresses linked to Sepolia Etherscan
  7. Auto-refresh every 15 seconds
  8. Dark theme, responsive design, zero external dependencies

    I built SqueekVision and wrote all the deliverables, but none of the required checks ran, so the assignment is incomplete. The shell would not start in this session: every command failed with "Sandbox is required but failed to initialize: Failed to create bridge sockets after 5 attempts". The browser tool also failed: "Browser "chrome-for-testing" is not installed". So nothing was built, tested, type-checked or rendered, and nothing is committed.

    What's in the repo:

    • The site (src/): plain HTML, CSS and two JavaScript modules with no dependencies, as the brief asks. It shows:

      • the Squeektoshi wheel status (running or idle, plus rotation, speed and distance);
      • a striped progress bar for the next block;
      • $SQK minted, circulating and max cap;
      • the settlements table with Now / 24h / 7d tabs;
      • an hourly bar chart from the 24h data;
      • the contract addresses, each linking to Sepolia Etherscan.

      There's a Refresh now button, a 15-second auto-refresh you can turn off, and a dark layout that changes at 46rem and 68rem wide. The page has a title, favicon, description, og:title and og:image.

    • The export (dist/): written by hand as a copy of each src/ file, because npm run build couldn't run. All asset links are relative.

    • Package files: package.json and a package-lock.json that lists no packages. Also scripts/build.mjs, tests/lib.test.mjs (12 tests of the data handling) and a type-check config.

    • Docs:

      • README.md: install, preview and rebuild steps, plus the verification status.
      • DESIGN.md: colours, type, layout and components, taken from the final source.
      • artifacts/validation.md: a review against the six Better Interface areas, done by reading the source. It found six issues (three medium, three low), all fixed. Each command is listed as not run.

    What I checked: I fetched all three API endpoints. Their real fields differ from the brief's wording, so the page uses what the API actually returns. The contract addresses come from the API's deployment record; none are typed into the code.

    Limitations:

    • Wheel and supply show dashes for now. On 2026-11-04 the API returned no wheel reading (measurement: null) and no supply (supply: null, "not yet safe"). The page explains this in place of each value.
    • Some field names and units are guesses. The names I look for in a wheel reading (rpm, speed, distance) are my best guess until the API publishes one. I also treat the block progress number as thousandths of a block, which the API doesn't document.
    • CORS is unknown. If the API doesn't allow requests from other sites, each panel will say it didn't load, and the header gives the reason and a retry hint.
    • The share image is an SVG. Some link previews only accept PNG or JPEG.

    To finish: with a working shell, run npm run check, npm test, npm run typecheck and node .imd/reads/skills/design-critic/scripts/taste.mjs --out test/scratch/taste, then look at the page at 390 wide and commit. npm run check confirms dist/ matches src/ exactly, which matters because I copied it by hand.
