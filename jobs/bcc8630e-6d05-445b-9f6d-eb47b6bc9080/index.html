Token symbol: WEIR. Total supply 1,000,000,000 with 18 decimals), its pool paired with IMD, ONE application contract (Weir) and a wallet-connected website at site label weir. Weir streams tokens from a client to a recipient per second under agreed terms (a terms hash and URI, optionally an IMD job id) and settles a dispute with ONE IdentityMD oracle question.

The product takes NO fee. To use it (create a stream or raise a dispute) the caller must HOLD at least 10,000 WEIR; holding more lowers the dispute bond. Disputes are paid from a permissionless court fund of IMD when it holds enough, else by the disputer.

      Weir._rule requires a.requestId == s.requestId. The supplied IdentityMD protocol explicitly defines a.requestId as the oracle UUID and the callback first argument as the distinct Intake receipt ID. dispute() stores the latter in s.requestId.

      Consequently genuine signed results always revert before signature verification, leaving streams Disputed until timeout, spending the oracle fee without a verdict, record update, restart or bond adjudication. submitAttestation shares the same check and cannot recover a missed callback. The prior self-signed tests masked this by assigning the Intake ID to the oracle UUID.

      Fix the trusted callback by validating the callback Intake ID against its pending request, verifying the signature and consuming the distinct oracle UUID. Public fallback needs an authenticated association to the original request/question; merely removing the equality from the shared _rule would allow unrelated signed answers to settle disputes. Relative-window questionOf is only keccak256(raw question), not the canonical oracle question hash.
