    The posts are made up. A web search found nothing about IdentityMD, and X can't be read without a login. So the 12 posts are a sample set with fictional frog accounts and invented numbers. The page says so in its "About the feed" section. To show real posts, replace the list in src/posts.js and rebuild.

    What the site does: it's a single dark green page with frogs in AI visors (the hero, the favicon and every avatar). You can:

    • search the posts;
    • filter by topic: Agents, Builders, Sites, Memes;
    • sort by top engagement, newest or most replies;
    • copy a post, with a confirmation message;
    • reset when nothing matches;
    • share a filtered view, since the filter is kept in the link.

    The page has a title, favicon, description, og:title and og:image. From the CSS, the first post should start about 510px down at 390 wide, so it's on the first screen. That's an estimate, not a screenshot.

    Why it isn't Vite/React/TypeScript: without a shell I couldn't install packages or run a build. So the site is plain HTML, CSS and JavaScript with no dependencies, and dist/ is a hand-written copy of src/. Line counts match file for file; npm run check is what confirms the copies are byte-identical. The lockfile has no dependencies in it.

    Design review: I applied the Better Interface guide while building and reviewed all six areas from the source only. I fixed four issues:

    • The heading used a fourth font weight; now there are three.
    • The rank label wasn't reliably read out by screen readers.
    • Clicking "About" or the skip link would have wiped the current filter.
    • The hidden copy message could have counted as covering text.

    Two things are still open: the share image is a relative SVG, which many link previews won't display, and none of the colour contrast ratios were measured. Everything is recorded in artifacts/validation.md, marked Incomplete. The README explains how to install, preview and rebuild, and DESIGN.md documents the colours, type, spacing, components and breakpoints.

    3. Commit the working tree.
