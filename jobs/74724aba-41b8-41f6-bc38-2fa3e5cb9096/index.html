Contract LastWord: one public billboard message of up to 140 characters that anyone can replace.

Before the project's token is connected, replacing the message is free, at most once per wallet every 10 minutes.

After the token is connected, replacing the message burns tokens: the new author sends them to 0x000000000000000000000000000000000000dEaD with transferFrom (approve first). The first paid message burns at least 1,000 tokens, and each next one at least 10% more than the previous burn. If nobody replaces the message for 24 hours, the minimum goes back to 1,000 tokens.

Emits MessageSet(author, text, burned, timestamp). Keeps the last 50 messages readable, and the total tokens burned.

No ETH, no fees, holds no funds, not upgradeable, not pausable.

Website: the current message very large in the middle with its author and how long it has stood; a form to post a new one that shows the minimum burn and, once the token is connected, an Approve then Post flow; the last 50 messages below; the total burned.

Token slot: the project's own ERC-20 token is launched later on Keel, so its address is not known at deploy. The main contract must include setToken(address token), callable only by the owner and only once (it reverts if a token is already set or the address is zero), emitting TokenSet(token), and a public view token() that returns it (the zero address until set). Every feature that uses the token stays disabled until it is set. The website reads token() and hides token features until it is set.

The owner of every deployed contract is 0xb77161bbaf98470c6c5101899d30df413f9a019d (the creator's wallet), set in the constructor; the deployer keeps no rights.

Deliver: (1) the smart contracts for this, tested and reviewed, then deploy LastWord on chain to Ethereum mainnet (chain 1) — contracts only, no token; (2) publish the source code to a public GitHub repository; (3) a user-facing website that uses the deployed contract addresses, where people connect a wallet and use them, published at a public URL on IPFS.
