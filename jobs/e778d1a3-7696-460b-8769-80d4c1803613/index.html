Build a complete responsive web application called Squeek Radar – Live Activity & Event Monitor.

Purpose: A public tool that monitors real-time hamster activity and events on Squeekchain. Anyone can use it without owning an NFT, staking SQK, playing games, or connecting a wallet.

1. Official API

Use the official documentation: https://docs.squeekchain.com/developers/api/

API base: https://api.squeekchain.com/v1

Use these documented endpoints:

  • /status
  • /events?category=measurement
  • /measurement/runs
  • /measurement/blocks
  • /measurement/stats?range=7d
  • /settlements?range=24h

Use real API data. Never fabricate values or events. Handle unavailable, stale, and missing data correctly. Missing data must not be displayed as zero.

2. Main Features

A. Live Activity

  • Current hamster status.
  • RPM and speed.
  • Today's distance.
  • Cumulative work units.
  • Last updated time.
  • Freshness indicator: Fresh / Stale / Unavailable.

B. Live Event Feed

Display actual events from the API:

  • Distance milestones.
  • Daily distance milestones.
  • Speed milestones.
  • New speed records.
  • Distance streaks.

Show event title, description, timestamp, and relevant values. Newest events first.

C. Milestone Radar

Show achieved distance, daily distance, speed, and activity streak milestones. Only mark milestones achieved when supported by actual API events.

D. Round & Block Monitor

Show round activity, work recorded, provisional blocks, block height, threshold, and confirmed settlements. Clearly distinguish provisional from confirmed data. Round duration is 600 seconds.

E. Alert Center

Detect new events, avoid duplicates, show timestamps, and allow users to mark alerts as read. Optional browser notifications must require user permission.

3. Dashboard

Create a home dashboard showing:

  • Current hamster activity.
  • Latest important event.
  • Latest milestone.
  • Block progress.
  • Recent events.
  • A short "What just happened?" summary based only on real data.

4. Design

Use a polished modern Web3 dashboard:

  • Dark navy/black theme.
  • Purple and blue accents.
  • Clean cards, charts, and icons.
  • Responsive desktop and mobile layouts.
  • Smooth animations.
  • Clear loading, error, and empty states.

5. Technical Requirements

  • Build a fully functional application, not just a visual mockup.
  • Integrate the real public API.
  • Use reusable components and clean code.
  • Refresh live data approximately every 5–10 seconds.
  • Cache historical statistics and avoid excessive API calls.
  • Keep working if an individual endpoint fails.
  • Do not add wallet connections, staking, tokens, or smart contracts.

Important data rules:

  • Distinguish accepted measurements from confirmed blockchain settlements.
  • Never label provisional blocks as confirmed.
  • Measurement runs are not necessarily SqueekCore-certified.
  • Clearly show stale or unavailable data.
  • Respect API coverage and UTC time boundaries.
  • Do not invent round IDs or unsupported events.

6. Deliverables

Provide:

  • Complete working application.
  • All five functional sections.
  • Real API integration.
  • Responsive interface.
  • Complete source code.
  • README and setup instructions.
  • GitHub-ready project structure.

Build the entire application now. Do not stop at a landing page or static demo. Prioritize real functionality, data accuracy, and usability.

Tagline: Know what's happening on the wheel.

MANDATORY GITHUB REQUIREMENT

Create a public GitHub repository named squeek-radar.

  • Upload the complete application source code.
  • Include README.md with project description, setup instructions, API integration, and deployment guide.
  • Include all required configuration and dependency files.
  • Include tests and source code, not just screenshots or a build.
  • Provide the actual GitHub repository URL in the final delivery.
  • Verify that the repository is accessible and contains the complete source code.

Do not consider the project complete until the GitHub repository has been created and the source code has been successfully pushed.

If GitHub authorization or access is required, clearly tell me what action is needed.
